# Запуск в Docker

При добавлении в группу бот просит включить темы и выдать ему права администратора
с разрешением «Управление темами». Когда настройки готовы, он создаёт тему
«Дедлайны» и обрабатывает сообщения и кнопки в группе только внутри неё.
Личные сообщения работают как раньше. ID темы сохраняется в БД, поэтому
перезапуск или повторное добавление бота не создаёт новую тему.
Права проверяются при их изменении; включение тем проверяется каждые 15 секунд,
пока тема не создана. Для немедленной проверки есть кнопка «Проверить настройки»
и команда `/setup` в группе. Бот сам не может включить темы или выдать себе права.
Перед запуском без Docker примените миграции: `alembic upgrade head`.

В личке учётная запись определяется по ID пользователя, а в группе - по ID чата.
В теме «Дедлайны» достаточно один раз указать учебную группу: все участники
используют общую запись в `users`, общие настройки `/profile` и дедлайны.
Напоминания этой записи отправляются в тему «Дедлайны». Личные настройки
участников не изменяются. Ввод задания и подтверждение остаются отдельными
для каждого участника, чтобы одновременное добавление не мешало другим.

Бот ежедневно отправляет расписание с кнопкой дедлайнов на сегодня и завтра.
По умолчанию уведомления включены и приходят в 08:00 по Москве.
В `/profile` две кнопки в одном ряду показывают время и статус уведомлений.
Нажмите на время и отправьте новое в формате `hh:mm` (00:00-23:59).
Кнопка статуса включает или отключает уведомления. Настройки сохраняются в базе.
При вводе времени или новой группы `/cancel` отменяет изменение.
Команда `/reminder` позволяет получить расписание вручную.
При запуске без Docker перед обновлением бота примените миграции: `alembic upgrade head`.
Команда `/deadlines` показывает только дедлайны группы на текущую неделю
с понедельника по воскресенье включительно (по московскому времени).
Команда `/all_deadlines` показывает все дедлайны группы начиная с сегодняшнего дня
включительно (по московскому времени), без ограничения конечной даты.
Рассылка работает, пока запущен бот; пропущенные во время остановки напоминания
не отправляются задним числом. Запускайте один экземпляр бота, чтобы избежать дублей.

```bash
docker compose up -d --build
```

Адрес API расписания задаётся через `API_PATH` в `src/settings/.env`.
Для адреса `http://schedule-api:8000` контейнер API должен быть подключён
к сети `poly-shared` и иметь в ней имя сервиса или сетевой alias `schedule-api`.
Бот подключён к этой сети и к стандартной сети проекта для доступа к `db`.
Сеть `poly-shared` внешняя: её должен заранее создать проект API.

После изменения сетевых настроек пересоздайте контейнер бота:

```bash
docker compose up -d --force-recreate bot
```

Проверить разрешение имени API из контейнера бота:

```bash
docker compose exec bot python -c "import socket; print(socket.getaddrinfo('schedule-api', 8000))"
```

## Вложения к дедлайнам

После `/deadline` отправьте фото или документ с текстом задания и датой в подписи.
Можно отправить несколько файлов альбомом. Если у вложения нет подписи, бот
сохранит его на время ввода и попросит отправить текст задания следующим сообщением.
При уточнении предмета вложения сохраняются; `/cancel` отменяет весь ввод.
Текст внутри фотографий и документов не распознаётся — нужна подпись или сообщение.

В базе хранятся тип вложения и Telegram `file_id`; скачивать файлы на сервер не нужно.
Вложения отправляются после текста в `/day`, `/nextday`, `/week`, `/deadlines`,
`/all_deadlines`, `/reminder` и утренней рассылке с указанием задания и даты.
Существующие дедлайны получают пустой список вложений.

Перед запуском обновлённого бота без Docker: `alembic upgrade head`.
При запуске через Docker миграция применяется автоматически.

Проверки: `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v`.

При повторном добавлении задания для той же группы, даты и предмета бот сравнивает
его с существующими. ИИ объединяет дополнительные совместимые подробности того же
задания, сохраняя старые сведения; разные номера работ или темы остаются отдельными
дедлайнами. Новые вложения добавляются к найденному заданию, повторные файлы
отсеиваются по `file_unique_id` (для старых вложений — по `file_id`).
Если текст полностью совпадает, файлы добавляются без дополнительного обращения
к ИИ. При изменениях бот отвечает «Дедлайн обновлён» и показывает итоговый текст
и количество вложений. Если новой информации нет, запись остаётся прежней.
Содержимое файлов ИИ не анализирует.

В расписаниях `/day`, `/nextday`, `/week`, `/reminder` и утренней рассылке ДЗ и вложения открываются кнопкой «Показать дедлайны». Для `/reminder` и рассылки кнопка показывает задания на сегодня и завтра.
